# Phase 4 foundation integration

This commit delivers authentication, shared shell and clinic settings. It does not deliver the schedule, patients or agent editor (Tasks5/6), and is not the Phase4 owner checkpoint. Only implemented navigation is shown. The setup checklist explicitly reports the pending agent-editor integration rather than supplying an inactive link. Task5 should replace the index redirect with the completed-clinic schedule destination; Task6 should replace the agent checklist note with the actual agent route.

## Shared interfaces

`useAuth()` exposes `me`, `sessionId`, `request`, `logout`, `isManager`, `registerCleanup`, plus auth entry points. `request('PATCH /resource/{identity}', {params:{identity},body,signal,idempotencyKey})` is typed from `DashboardOperations`. Literal endpoint templates select generated request and response types. Mutation retries must reuse the same key for the same reviewed user intent. Register media cleanup with `registerCleanup(() => media.disconnect())`; this is required when Task6 mounts voice. Tokens are private to Session memory and never returned by the hook. Use `useSessionKey(...)` for every feature query. Session reset aborts requests, clears QueryClient and invokes registered media cleanup. A generation fence rejects results even if an underlying fetch ignores abort. Singleflight refresh handles both simultaneous401 and a late401 after rotation.

`routes` is a React Router DataRouter configuration, compatible with real `useBlocker` in Task6. `PageHeader`, `ErrorSummary`, `StatusBadge`, `EmptyState`, `ConfirmDialog`, `ContractForm`, and shared CSS provide page/form/table treatments. A form validates generated JSON schemas, maps server field arrays/maps, disables fields during save and preserves inputs on failure. Use focused feature components for complex agent editing rather than exposing raw config objects in this general-purpose form.

`useDashboardQuery`, `useRefreshClinic`, `useCatalog` provide session-scoped clinic data. Catalog selectors fetch every page; visible tables paginate25 records. Availability is a single server snapshot. Friday/Ramadan edits preview server changes and apply the identical body/revision with a stable per-review key. No client-side delete/create template chain exists. Closures remind only within14 calendar days of a manually configured start date in the clinic timezone.

## Reviewed edit and request lifecycles

ContractForm retains dirty values and their original server revision across refetches. Clean forms reconcile with fresh data; dirty forms show a confirmation to discard edits and reload current saved values. Do not key editors by server revision. `beforeSave` supports a contextual review of the submitted snapshot: clinic timezone changes show saved → proposed zone, cancel performs no PATCH, and confirmation applies only to that exact proposal. Login passwords use current-password autocomplete; account creation uses new-password.

Availability previews keep the original editor mounted and dirty (`resetOnSuccess=false`), so returning from a rejected apply preserves entered hours and the captured revision. Provider/template switches are disabled during preview/apply. Network, timeout and server failures after apply retain the reviewed payload/key and keep switching locked until an idempotent retry resolves the uncertain outcome. A definitive client/conflict rejection allows returning to edit/reload. Successful apply intentionally creates a fresh editor after the authoritative refresh. Closed exceptions always submit null start/end times, including edits to existing closed rows and custom-to-closed conversions.

## Task 5 integration

Schedule, Patients and patient detail routes are lazy modules. Existing clinics with persisted profile/providers/services/hours land on Schedule; incomplete clinics land on Setup and Schedule shows a contextual reminder. Agent editor/navigation remains Task6. Clinic configuration links are grouped under Clinic settings; mobile Menu appears before the navigation in DOM order and Escape returns focus.

Scheduling consumes the paginated joined `/dashboard/appointments` projection with a bounded clinic-local day/week date range. That endpoint converts its date bounds to UTC on the server; no invented UTC query parameters are sent. Temporal computes local display/day/week boundaries independently of the browser zone. Offered UTC slot instants are submitted unchanged; repeated clock times display UTC offsets. Reschedule review derives its end from the original appointment duration, preserving its snapshot rather than using an edited service duration. The authoritative mutation still checks saved buffers/policy. Booking/reschedule/cancel and merge carry explicit review/confirmation and stable retry keys; uncertain booking/merge outcomes keep their reviewed intent locked. Server conflict alternatives are bounded/validated before display.

Patient search is debounced, abortable and server-paginated in memory; browser routes contain only opaque IDs. Managers explicitly select both identities and each retained field (including null Urdu name/DOB), review affected history counts, then merge with both captured revisions. Shared phones never infer identity. Source tombstones remain read-only with a retained-record link. Legacy staff edit uses the existing PUT contract, which has no revision parameter; merge optimistic concurrency is server-owned.

Task5 automated evidence uses synthetic typed HTTP fixtures. Browser checks render the actual calendar under an Asia/Tokyo browser and America/New_York clinic, inspect 1440/1024/390 layouts and mixed Urdu text, and exercise reviewed booking and merge dialog dismissal. This is not live API or owner acceptance evidence. Real deployment/API validation remains Task7.

## Task 5 review fixes

Schedule owns one captured appointment workspace and its synchronous mutation lock. Calendar/list callbacks cannot replace an open workspace; pending or uncertain booking/reschedule/cancellation prevents Close, Escape, outside dismissal and competing selection. The cancellation snapshot retains its appointment and key across network,5xx and408 retry. Booking/reschedule communicates its lock to the owner before dispatching. Keep future selection paths behind this same owner guard; do not key an editor by a mutable calendar selection. Other features' ConfirmDialog behavior is unchanged: scheduling now uses its own single controlled dialog for details, editing and cancellation.

The compact schedule has a600px calendar viewport with all00–24 reachable, an08:00 starting scroll, human date heading, two-row mobile toolbar, and an explicit List alternative. Event heights follow the actual time grid; supported v7 slotMinHeight controls the reading scale. Long calendar names use a complete text-line ellipsis box with adequate Nastaliq height. Short events show time/name; full patient/service/provider values remain in details and hover text. Mobile list rows expand for full Urdu content. Booking/reschedule opens in the focused dialog; review hides editable fields and returns focus on edit/dismissal. Exact UTC instants and original reschedule duration remain authoritative.

The review fix evidence remains synthetic HTTP fixtures, including two-appointment pending/503 replacement attempts,503/408 cancellation dismissal attempts, focused dialogs and real day/week/night calendar rendering at1440/1024/390. A ResizeObserver notification remains observed in Vite responsive runs; production preview has not been tested and the cause is unconfirmed. Task7 retains that probe and the shared bundle follow-up.
